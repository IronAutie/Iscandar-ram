# The C translation of the engine

The Python engine is the specification. The C in this folder is its
transcription, admitted under the standing rule: C is admitted only
where it reproduces the Python and paper oracle outputs exactly.
The Python remains the oracle and the offline tooling; no Python
runs in the serving arrangement.

## k3/

The k=3 engine transcribed to C: foundation modules (Geometry,
Coordinate, Bijection, MPUPointer, the Nothing/Error sentinels),
the request modes (Nano, Tiny, Small, Large, Huge), the Mode/Modes
dispatch, and the allocator Engine, with the author's gear C linked
unchanged so the search cursors behave as they do under the Python.

Admission evidence, generated against the Python oracle:

- `gen_foundation_vectors.py` and `foundation_vectors_expected.txt`:
  101 vectors; `FoundationCheck.c` runs the identical script
  against the C; the diff is empty.
- `gen_engine_vectors.py` and `engine_vectors_expected.txt`:
  7,523 operations driven through the Python Engine;
  `EngineCheck.c` replays them against the C; the diff is empty.
- `status.h` is generated by `gen_status.py` from `Status.py`
  (never hand-edited); per-site pointer refusal codes 20 to 25.

Source of record: the engine repository, commits e06da1b, 2c22b04,
44d68cb.

## k4/

The k=4 layer transcribed to C99: Beam, BeamCoordinate, CPUPointer,
and CubeEngine as an adapter holding one real k=3 C Engine per cube
behind the CubeEngine interface. Beam.c is unchanged by the adapter
step.

Admission evidence: `gen_k4_expected.py` drives the real Python
Beam over the real Python k=3 engine; `test_k4.c` replays it
against the C; the 68-line transcript diff is empty.
`run_k4_c_tests.sh` runs the suite.

Source of record: the iscandar-k4 repository, commits bd5ec85,
51d18ea.
